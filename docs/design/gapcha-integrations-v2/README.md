Дизайн-предложение от 3 ноября 2026 года. Макеты созданы встроенным imagegen по описанию ниже. Это визуальная концепция для Antigravity, а не опубликованный интерфейс. Рабочий код и база не менялись.

## Что реализовать

Сохранять существующую навигацию, бренд gapcha AI и рабочие функции. Подписи навигации на первом концептуальном макете не являются требованием переименовать разделы продукта.

Telegram: два режима «Мой аккаунт» и «Свой бот». Для аккаунта — три состояния процесса: сотрудник, подтверждение в Telegram, проверка подключения. Одна основная кнопка; короткая инструкция; длинные пояснения под «Нужна помощь?». Ссылку копировать отдельным действием, полный одноразовый URL не выставлять основным полем формы. Ссылку создавать только после действия пользователя, показывать её реальный срок действия. Открытие Telegram не равно успешному подключению. После возврата получать фактический статус сервера; предусмотреть истечение ссылки, повторную попытку, отказ и отзыв разрешений. Токен требуется только в режиме собственного бота. Требования Telegram и названия меню подтвердить актуальной официальной документацией; не переносить неподтверждённое требование Premium со старого интерфейса.

Каталог: компактная карточка виджета, одна строка пользы, три кратких свойства и одна кнопка «Настроить виджет». Небольшой пример чата справа. Без обещаний мгновенных ответов, установки за минуту и фиктивного статуса «онлайн». «Пример виджета» явно отделить от настоящего диалога.

Настройка виджета: вкладки «Оформление», «Установка», «Проверка». Выбор сотрудника, название чата, приветствие, доступные цвета, положение на сайте, сохранение и предпросмотр на компьютере/телефоне. Использовать фактические возможности API; неподдерживаемые параметры требуют реализации сохранения и применения на реальном виджете. В превью показывать несохранённые изменения, помечая их. Пример кода на макете условный: настоящий фрагмент генерировать из действующей интеграции. Не вставлять в публичный скрипт секреты сервера. Предоставить копирование кода и инструкцию, где его разместить. Проверка установки должна сообщать проверенный результат; сетевой отказ не является подтверждением отсутствия виджета.

Стиль: светлый нейтральный фон, белые поверхности, тёмный текст, коралловый акцент бренда; Telegram-синий для его действия. Единые контурные иконки из существующей библиотеки. Меньше вложенных карточек, эмодзи и рекламных формулировок. Без лишних градиентов, объёмных украшений и блёсток. Предусмотреть тёмную тему, русский/узбекский интерфейс, мобильную ширину, управление клавиатурой, заметный фокус и корректное закрытие модального окна. Состояния на макете — примеры, а не гарантия готовности подключения.

## Google: redirect_uri_mismatch

На присланном экране Google указана ошибка 400 `redirect_uri_mismatch`. Согласно официальной документации, переданный `redirect_uri` должен точно совпадать с разрешённым URI у OAuth-клиента с соответствующим `client_id`:
https://developers.google.com/identity/protocols/oauth2/web-server

В локальном `lib/calendar/google.ts` функция `resolveCalendarRedirectUri` выбирает явно переданный адрес, затем `GOOGLE_REDIRECT_URI`, затем origin с путём `/api/integrations/google-calendar/callback`. Обработчик `app/api/calendar/auth/route.ts` передаёт origin запроса. Настройки опубликованного окружения и Google Cloud в этой работе не проверялись.

Для домена chorla-ai.vercel.app ожидаемый адрес при отсутствии переопределения:
`https://chorla-ai.vercel.app/api/integrations/google-calendar/callback`

Antigravity: получить фактические `client_id` и `redirect_uri` из запроса авторизации без раскрытия секретов; проверить переопределение `GOOGLE_REDIRECT_URI` в Production; сообщить владельцу точный URI и OAuth-клиент, где его добавить в Google Auth Platform → Clients → Authorized redirect URIs. Существующий callback входа через Google сохранить: вход и подключение календаря используют разные маршруты. При изменении окружения Vercel нужен новый деплой. Проверить один и тот же URI при запросе разрешения и обмене кода. Не объявлять ошибку исправленной по одной локальной проверке.

## Промпты генерации

Макет 1: два артборда — компактное подключение Telegram с выбором сотрудника, тремя шагами, одной основной кнопкой и справкой; страница виджета с настройками, предпросмотром, примером кода. Русский интерфейс, светлая палитра gapcha AI, тонкие границы, строгая сетка, без декоративного «ИИ-стиля».

Макет 2: каталог интеграций с сохранением существующих пунктов меню; компактная двухколоночная карточка «Чат на сайте» с кратким описанием, кнопкой настройки и примером виджета; ниже карточки Telegram, Instagram Direct и Google Календаря. Единые иконки и спокойные статусы без неподтверждённых обещаний.

## Ограничения работы

Реализацию выполняет Antigravity по запросу владельца. Не применять миграции к рабочей базе автоматически и не воспроизводить старую очередь живых диалогов. Визуальные макеты не заменяют проверки реального подключения и обмена сообщениями.
