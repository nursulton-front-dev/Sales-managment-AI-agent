# Chorla AI — внедрение Design Pack

Проверено 26 октября 2026 года. Рабочая ветка: `redesign/chorla-design-pack-integration`. Ветка для GitHub: `redesign/chorla-design-pack-ready`.
Локальная реализация проверена. Полная приёмка для production остаётся открытой из-за общего lint, отсутствующих продуктовых функций и непроверенных внешних подключений, перечисленных ниже. Production не публиковался, рабочие данные не изменялись.

## Что реализовано

- Общая светлая/тёмная тема, системное переключение, адаптивная навигация, серверная роль администратора, мобильное меню и диалоги с удержанием и возвратом фокуса.
- Обзор с настоящими показателями и состояниями подключения; лиды с поиском, фильтрами, таблицей, канбаном и недельным списком фактических записей. Выдуманные свободные часы убраны.
- Диалоги с историей, состояниями ошибок, ручным перехватом и безопасным текстовым представлением сообщений. Пустой экран не позволяет отправлять сообщение.
- Редактор сотрудника: имя, услуги, прайс, вопросы, инструкции; ссылка с обзора открывает нужного сотрудника. Сохранение использует ответ сервера.
- Telegram, Instagram, WhatsApp и Google Calendar представлены отдельно. Подключение Telegram использует общую серверную реализацию для мастера и страницы интеграций; ошибки проверки не выдаются за отключённый канал. Расписание редактируется в интеграциях.
- Песочница на 600 px и на весь экран телефона, отдельная история для каждого сотрудника, повторная попытка после ошибки. Браузерный endpoint принудительно включает sandbox независимо от тела запроса.
- Тарифы и докупки из `lib/pricing.ts`, настоящий баланс и история. Прямые запросы браузера не могут начислять оплаченные токены.
- Компания и команда с реальными данными владельца; профиль с действующим изменением имени/пароля и просмотром сессий.
- Поддержка: создание, история, переписка, ответ администратора, внутренние заметки, повторное открытие. Вложения PNG/JPEG/PDF проверяются на сервере и доступны по приватным маршрутам.
- Устранены доверие к одному workspace cookie, обход пароля, произвольное изменение чужих агентов/лидов и выдача секретных полей клиенту. Верификация email использует OTP действующей auth-системы.
- Списание токенов и журнал объединены в одну SQL-команду для PostgreSQL. Локальный вариант выполняет изменение без промежуточного `await`. Записи через настроенную БД возвращают результат БД и не требуют записываемого локального диска.

Существующий логотип сохранён. Ассеты сравнивались перед копированием. Цены START/BUSINESS/PRO — $29/$59/$119; исходный каталог тарифов не изменён. Демонстрационные клиенты, роли, SLA и успех оплаты из PNG не переносились в рабочие данные.

Браузер работает с настоящими ответами локального API и отдельными тестовыми аккаунтами. Проверены неверный/верный пароль, поддельный workspace cookie, межорганизационные запреты на изменение сотрудника/лида и чтение обращения/вложения, валидация данных, сохранение редактора, защита баланса от неоплаченных запросов. Сбой транспорта подставляется только для проверки представления ошибки.

В модульных тестах используются настоящие локальные репозитории баланса и поддержки. Транспорт модели, SQL-адаптер и роли подставлены явно: это проверка ветвлений, а не доказательство работоспособности внешних сервисов. Проверены отсутствие внешних действий успешной песочницы, история OpenAI/Gemini, отсутствие списаний при недоступной модели, отказ при неуспешном списании, параллельные локальные списания и цикл ответа поддержки без утечки внутренних заметок.

Ручное сравнение выполнено по скриншотам реализованных экранов и `references`. Данные на снимках тестовые. Отдельного тёмного референса в архиве нет. Это не пиксельное совпадение и не полный аудит WCAG; Safari/Firefox и все варианты наполненной переписки не проверялись.

## Остающиеся ограничения

- **Оплата:** процессор, проверка подписи webhook и идемпотентная обработка платёжных событий отсутствуют. Выбор тарифа не меняет баланс; API возвращает явную недоступность. Нужны реализация и тесты платёжного провайдера.
- **Команда и профиль:** приглашения, дополнительные роли участников и смена email отсутствуют в действующей модели. Интерфейс честно обозначает недоступность. Загрузка логотипа компании и расширенные реквизиты также не реализованы.
- **Каналы:** WhatsApp и автоматические напоминания недоступны. Живые подключения Telegram/Instagram/Google Calendar, доставка писем и платные ответы моделей не выполнялись. Нужны тестовые приложения/аккаунты и реальные настройки окружения.
- **База:** SQL-ветка списаний проверена типами и сборкой, но ещё не испытана на живом PostgreSQL под конкурирующей нагрузкой. Локальное файловое хранилище рассчитано на один процесс; auth без DATABASE_URL хранится в памяти и теряется при перезапуске.
- **Существующие backend-ограничения перед запуском живых каналов:** `lib/ai/gateway.ts` в live-ветке определяет намерение записи по ключевым словам и назначает фиксированное время на завтра. Нужен отдельный корректный цикл выбора/проверки/подтверждения времени; песочница эту ветку не выполняет. Выдачу trial-бонуса также нужно объединить с регистрацией выдачи в одну транзакцию и обеспечить уникальность на уровне БД.
- **Проверки репозитория:** общий lint не зелёный; список оставшихся файлов сохранён. Сборка предупреждает об устаревшем `middleware` и широком filesystem tracing. Это не ошибки сборки.

## Окружение и preview

Новых колонок и миграций в этом изменении нет. В целевой БД должна присутствовать существующая схема `src/db/schema.ts`, включая auth, support и token logs. Миграции к рабочей БД не применялись.

Для полноценного preview нужны отдельная БД, `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET`, конфигурация почты (`RESEND_API_KEY`, `EMAIL_FROM`), приложения OAuth и ключ выбранной модели. Для Telegram нужен публичный HTTPS origin (`APP_URL` либо `BETTER_AUTH_URL`); callback-адреса внешних приложений должны соответствовать preview. Администратор задаётся `ADMIN_EMAIL`/`SUPERADMIN_EMAIL` и подтверждает email.

`.vercelignore` сохраняет runtime PNG из `public`, исключает макеты, отчёты, архив и локальный установщик. Удалённый preview не создавался.

Для воспроизведения браузерной приёмки сначала запустите отдельный сервер (Node 24, зависимости установлены):

```sh
env DATABASE_URL='' \
  BETTER_AUTH_URL='http://localhost:3100' \
  BETTER_AUTH_SECRET='isolated-local-test-secret-never-use-in-production' \
  CHORLA_DATA_DIR='/tmp/chorla-design-acceptance' \
  OPENAI_API_KEY='' GEMINI_API_KEY='' DEEPSEEK_API_KEY='' \
  RESEND_API_KEY='' GOOGLE_CLIENT_ID='' GOOGLE_CLIENT_SECRET='' \
  INSTAGRAM_APP_ID='' INSTAGRAM_APP_SECRET='' \
  NEXT_PUBLIC_SUPABASE_URL='' NEXT_PUBLIC_SUPABASE_ANON_KEY='' \
  node node_modules/next/dist/bin/next dev --port 3100
```

В другом терминале:

```sh
node scripts/verify-design-pack.cjs
node scripts/test-design-risks.cjs
```

Скрипт браузера создаёт аккаунты только на loopback-адресе; для изоляции данных обязателен именно сервер с приведёнными настройками. Во время снимков не изменяйте исходники и не запускайте сборку рядом с dev-сервером: проверка должна использовать одну версию ассетов.
