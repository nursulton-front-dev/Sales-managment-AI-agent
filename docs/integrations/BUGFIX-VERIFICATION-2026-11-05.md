# Исправления подключений — 5 ноября 2026

Изменения подготовлены локально. Коммит, отправка в GitHub и публикация в этой работе не выполнялись. Рабочие данные не удалялись; миграции не применялись; реальные сообщения клиентам не отправлялись.

## Подтверждённые дефекты и исправления

- PostgreSQL: `redeemTelegramBusinessBindingForUser` выбирал несуществующую колонку `nonce` вместо `id`. `RETURNING *` выдавал snake_case, тогда как webhook читал `workspaceId`/`agentId`. Исправлены имя колонки и алиасы; добавлена блокировка выбранной записи. Проверка одноразовой ссылки не позволяет второму Telegram-пользователю перезаписать подтверждённого владельца.
- Telegram: актуальный `BusinessConnection` передаёт разрешение на ответы в `rights.can_reply`. Обработчик использует его, сохраняя совместимость со старым форматом. Пустой объект `rights` не подменяется старым разрешением. Источник: https://core.telegram.org/bots/api#businessconnection .
- Расписание: сервер принимал только строгое ASCII `HH:mm-HH:mm`, отклоняя варианты с пробелами, тире и однозначным часом. Общая нормализация приводит допустимый диапазон к каноническому виду; неверные часы, равные границы и обратный диапазон по-прежнему отклоняются. В интерфейсе вместо свободного текста два поля времени. Точный исходный PATCH пользователя и содержимое его рабочего расписания не получены: совпадение этого дефекта с каждым присланным HTTP 400 не утверждается.
- Instagram: Unified Login явно запрашивает возврат `code` через `override_default_response_type=true`; callback формируется одинаково в начале и конце авторизации без двойного слеша. Ошибка обмена кода Meta больше не запускает обмен этого же кода у другого провайдера. Facebook-объект без признаков Instagram-профиля не принимается за профиль Instagram при прямом lookup.
- Instagram: callback выдаёт фиксированный код этапа (обмен, профиль, webhook, сохранение), который страница отображает понятным текстом. Произвольный текст ошибки провайдера в баннер не попадает. Успех показывается только после сохранения подключения; баннер после возврата дополнительно сверяет статус текущей компании.
- Интерфейс: недоступность проверки Telegram не маскируется обычным «Не подключён». Запросы статусов выполняются без кеша.
- Сборка: убраны неподдерживаемые именованные экспорты `maskEmail` и `handleCalendarCallback` из route-файлов Next.js; оба callback календаря используют экспортируемый HTTP GET. Логика входа не менялась.
