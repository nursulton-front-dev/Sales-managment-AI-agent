Проверено 2 ноября 2026 года чтением Vercel CLI/API, локального коммита и `vercel.json`. Изменений кода, переменных Vercel, базы данных или внешних настроек в ходе диагностики не выполнялось.

## Подтвержденные факты

- Проект: `ai-business-os`.
- Неудачный Production: `ai-business-o9xgigcpx-nursultans-projects-c3c55b7b.vercel.app`.
- Deployment ID: `dpl_CdRoCMnvwd3HWvujwyg4jQXTBe9J`.
- Коммит: `0b9e2c9c18f2c93245d442b63e273e98f649e9de`, ветка `main`.
- API Vercel вернул `readyState: ERROR`, `plan: hobby`.
- `errorMessage` прямо сообщает, что Hobby допускает только ежедневные cron-задачи, а выражение `* * * * *` запускается чаще одного раза в сутки.
- Именно это выражение находится в `vercel.json` для `/api/cron/channel-events`.
- В списке Production предыдущий успешный деплой имеет статус READY и коммит `52dea482ed00075c5d07ab654a528b97552be6ac`. Привязка пользовательского домена к конкретному деплою отдельно не проверялась.
- Meta показывает отказ проверки webhook. Проверка ответа webhook из диагностической среды не завершена: первоначальный запрос был заблокирован сетевым доступом, а автоматическая проверка разрешения для повторного запроса не уложилась в срок. Поэтому текущий HTTP-ответ webhook и совпадение токена не утверждаются.

Нельзя считать новый коммит опубликованным или новую переменную примененной только потому, что выполнен push. Изменения переменных Vercel применяются к новому деплою; неудавшийся деплой не подтверждает их использование текущим сайтом.

3. Обеспечь поддерживаемый механизм регулярного восстановления очереди с нужной задержкой для автоответов. Если нужен внешний планировщик, подготовь его конфигурацию, требования к секрету, способ наблюдения за запусками и конкретные действия владельца. 4. Сохрани авторизацию worker через `CRON_SECRET`, ограничения параллелизма, порядок сообщений, ручной перехват, защиту от повторной отправки и повторного списания. Не запускай рабочую очередь для теста и не воспроизводи старые сообщения живым клиентам.
